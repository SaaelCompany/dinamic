# Portal Dynamic Fields — дополнительные поля на портале Jira Service Management

Плагин для Jira Server/Data Center 8.21 и Jira Service Management 4.21.
Поля, варианты ответов и условия показа задаются **в самом плагине**. Пользовательские поля Jira создавать не нужно: на портале рисуется свой блок, а ответы сохраняются в заявке и видны сотруднику поддержки.

```
[x] Медицинский сотрудник
      ├─ [x] Основная специальность
      │        ├─ Профиль                 (список)
      │        ├─ Стаж                    (текст)
      │        └─ [x] Есть сертификаты
      │                 └─ Перечень сертификатов
      └─ [ ] Дополнительная специальность
               └─ Дополнительный профиль  (список)
```

Вложенность не ограничена. Поле может зависеть только от поля, которое стоит выше, поэтому цикл невозможен. Скрытие ветки очищает её ответы, и в заявку они не попадают.

## Сборка

Нужны **JDK 8** и **Maven 3.6+**. Atlassian SDK не обязателен.

```bash
mvn clean package
# target/portal-dynamic-fields-2.7.1.jar
```

На JDK 11/17/21 профиль `jdk9-plus` включает `--release 8`, байткод остаётся версии 52, и Jira 8.21 его загружает:

```bash
unzip -p target/portal-dynamic-fields-2.7.1.jar ru/saael/dynamicfields/rest/RulesResource.class | head -c 8 | xxd
# ... 0000 0034  -> major version 52 = Java 8
```

Локальная Jira с плагином (скачивает Jira 8.21.1 и JSM 4.21.1):

```bash
mvn jira:run
# http://localhost:2990/jira  admin / admin
```

Пока `jira:run` запущен, обновляйте плагин командой `mvn package` **без** `clean`: QuickReload подхватит jar. `clean` удалит `target/jira` вместе с работающей Jira.

## Установка

1. Администрирование → Приложения → Загрузить приложение → `portal-dynamic-fields-2.7.1.jar`.
2. Приложения → **Динамические поля → Динамические поля портала** (или `/plugins/servlet/dynamic-fields/admin`).
3. Вверху выберите **тип запроса**. В списке только его поля. Поля других типов скрыты.
4. «Добавить блок» или «Вставить пример». Новый блок относится только к открытому типу и не появляется на остальных. Поля стоят деревом, справа предпросмотр этого типа.
5. **Место на форме**: перед кнопкой отправки, в начале формы или после поля. Название поля пишите так, как его видит пользователь (например, «Тема» или «Описание»), без пометки «необязательно» в скобках.
6. «Сохранить». Обновите страницу портала этого типа запроса.

Блок без типа запроса на портале не показывается. Раньше пустой список означал «на всех типах»: после обновления такие блоки нужно открыть в пункте «Без типа запроса», выбрать тип и сохранить.

Страница настроек собрана из обычных панелей Jira. Сначала выбирается проект, затем тип запроса — чужие проекты в списке не мешают.

Узел — это вопрос. Ответы написаны на самом узле. Точку ответа перетащите на другой вопрос или нажмите её и затем вопрос: появится привязка. Нажмите линию, чтобы снять привязку. Сам вопрос перетаскивается на другой, чтобы изменить порядок. Плюс на ответе добавляет следующий вопрос. Поле формы, после которого стоит блок, в схему не входит.

Типы: флажки, переключатели, список, множественный выбор, текст, многострочный текст, число, дата, время, дата и время, ссылка. У списка пустой пункт по умолчанию называется «Не выбрано»; текст можно заменить. Если задан ответ по умолчанию, пустой пункт можно скрыть. Вопрос над ответами можно оставить пустым.

Блок можно поставить сразу после существующего поля формы, в том числе в середине. Если у этого поля есть варианты, блок можно показывать только при выбранных ответах.

Если после обновления страница выглядит пустой, установите jar **2.7.1** и обновите страницу с очисткой кэша (Ctrl+F5). Старые правила, которые прятали пользовательские поля Jira, больше не используются. Сохранённая форма версии 2.0 открывается как один блок.

## Что видит поддержка

После «Сохранить» каждый вопрос становится текстовым полем Jira с тем же названием. Ответ клиента записывается в это поле. На экране заявки слева по-прежнему виден блок **«Ответы с портала»**.

В автоматизации поле выбирается из списка полей задачи. Для вопроса «Специальность» условие такое: поле **Специальность** равно **Терапевт**. Триггер нужен «Задача обновлена»: портал записывает ответ сразу после создания заявки, поэтому триггер «Задача создана» значение ещё не видит. Несколько отмеченных ответов лежат одной строкой через запятую.

Записать ответы может автор заявки в течение 30 минут после создания, а также пользователь с правом редактировать задачу или администратор Jira. Читать их может тот, кто видит заявку.
