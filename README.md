# Portal Dynamic Fields — дополнительные поля на портале Jira Service Management

Плагин для Jira Server/Data Center 8.21 и Jira Service Management 4.21.
Вопросы задаются в плагине отдельно для каждого поля типа **Динамические поля**. Поле создаётся в настраиваемых полях Jira, затем его добавляют в нужный тип запроса. Ответы видны в деталях задачи.

```
[x] Медицинский сотрудник
      ├─ [x] Основная специальность
      │        ├─ Профиль                 (список)
      │        ├─ Стаж                    (текст)
      │        └─ [x] Есть сертификаты
      │                 └─ Перечень сертификатов
      └─ [ ] Дополнительная специальность
               └─ Дополнительный профиль  (список)
```

Вложенность не ограничена. Поле может зависеть только от поля, которое стоит выше, поэтому цикл невозможен. Скрытие ветки очищает её ответы, и в заявку они не попадают.

## Сборка

Нужны **JDK 8** и **Maven 3.6+**. Atlassian SDK не обязателен.

```bash
mvn clean package
# target/portal-dynamic-fields-2.9.0.jar
```

На JDK 11/17/21 профиль `jdk9-plus` включает `--release 8`, байткод остаётся версии 52, и Jira 8.21 его загружает:

```bash
unzip -p target/portal-dynamic-fields-2.9.0.jar ru/saael/dynamicfields/rest/RulesResource.class | head -c 8 | xxd
# ... 0000 0034  -> major version 52 = Java 8
```

Локальная Jira с плагином (скачивает Jira 8.21.1 и JSM 4.21.1):

```bash
mvn jira:run
# http://localhost:2990/jira  admin / admin
```

Пока `jira:run` запущен, обновляйте плагин командой `mvn package` **без** `clean`: QuickReload подхватит jar. `clean` удалит `target/jira` вместе с работающей Jira.

## Установка

1. Администрирование → Приложения → Загрузить приложение → `portal-dynamic-fields-2.9.0.jar`.
2. Администрирование → Задачи → Настраиваемые поля → Добавить. Тип поля — **Динамические поля**. Задайте имя, например «Анкета сотрудника».
3. Приложения → **Динамические поля → Динамические поля портала**. Для нового поля появился блок. Соберите в нём вопросы и нажмите «Сохранить».
4. В нужном проекте откройте тип запроса и добавьте это поле. На портале вопросы стоят на месте поля. На экране просмотра ответы этого поля видны в деталях задачи.
5. Обновите страницу портала с очисткой кэша (Ctrl+F5).

Каждое такое поле настраивается отдельно. Вопросы есть только в тех типах запросов, куда поле добавлено.

Узел — это вопрос. Ответы написаны на самом узле. Точку ответа перетащите на другой вопрос или нажмите её и затем вопрос: появится привязка. Нажмите линию, чтобы снять привязку. Сам вопрос перетаскивается на другой, чтобы изменить порядок. Плюс на ответе добавляет следующий вопрос.

Типы: флажки, переключатели, список, множественный выбор, текст, многострочный текст, число, дата, время, дата и время, ссылка. У списка пустой пункт по умолчанию называется «Не выбрано»; текст можно заменить. Если задан ответ по умолчанию, пустой пункт можно скрыть. Вопрос над ответами можно оставить пустым.

Если после обновления страница выглядит пустой, установите jar **2.9.0** и обновите страницу с очисткой кэша (Ctrl+F5). Старые правила, которые прятали пользовательские поля Jira, больше не используются. Сохранённая форма версии 2.0 открывается как один блок.

## Что видит поддержка

Ответы лежат в том поле, которое добавлено на экран просмотра. Отдельной панели «Ответы с портала» нет.

После «Сохранить» каждый вопрос дополнительно становится текстовым полем Jira с тем же названием. В автоматизации для вопроса «Специальность» условие такое: поле **Специальность** равно **Терапевт**. Триггер нужен «Задача обновлена»: портал записывает ответ сразу после создания заявки, поэтому триггер «Задача создана» значение ещё не видит. Несколько отмеченных ответов лежат одной строкой через запятую.

Записать ответы может автор заявки в течение 30 минут после создания, а также пользователь с правом редактировать задачу или администратор Jira. Читать их может тот, кто видит заявку.
